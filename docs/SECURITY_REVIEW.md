# Проверка безопасности и устойчивости локального MVP

Проверено 19 октября 2026 года по текущему коду и автономным тестам.
Это целевой просмотр перечисленных границ, а не независимый аудит безопасности.

| Граница | Результат и подтверждение |
| --- | --- |
| Секреты | `.env` игнорируется Git и отсутствует в списке отслеживаемых файлов; `.env.example` не содержит настоящего ключа. Клиент берёт ключ только из окружения, `SecretStr` скрывает его представление. Тесты HTTP/настроек проверяют отсутствие учебного секрета в ошибках и журналах. История всех прежних Git-коммитов не аудировалась. |
| SQL | Репозитории используют SQLAlchemy `select`, `insert`, привязанные значения и числовые ID. Пользовательский текст не вставляется в SQL-строки. Внешняя модель не выполняет SQL. |
| Загрузчик | Тайм-аут 20 секунд, ограниченные повторы, ограничение страниц/карточек и пауза; HTTP-перенаправления отключены. Robots.txt и ограничения доступа учитываются. Тесты используют HTTP-подмену, включая тайм-аут и отказ доступа. |
| Внешний API | Настраиваемый конечный тайм-аут (20 секунд по умолчанию, максимум 120), HTTPS без ключа в URL, перенаправления запрещены, не более двух попыток при неверном JSON. В ошибку пользователю не передаются HTTP-тело, заголовки Authorization или исходное исключение. |
| Недоверенный ответ | Pydantic проверяет намерение и объяснения локально. Неизвестные ID/причины отвергаются. Финальные карточки повторно читаются из SQLite; сгенерированные копии фактов не используются. |
| URL источника | `wine_url` разрешает только HTTPS-карточку `vino-svoe.ru/wines/<slug>`; slug проверяется моделью. Интерфейс повторно проверяет HTTPS и домен ссылки, открывает её с `noopener noreferrer`. Изображения браузер загружает только по HTTPS, с `no-referrer`; сервер их не скачивает. |
| Отображение | Текст добавляется через `textContent`; технические API-поля не пересылаются пользователю напрямую. Сервер возвращает краткое русское сообщение при 500; интерфейс использует ограниченный набор сообщений об ошибках. Проверено тестами API и JavaScript. |
| Целостность | Чтение рекомендаций не меняет каталог. Запись событий атомарна; неизвестный ID откатывает пакет. Новые тесты сравнивают все карточки и события до/после сбоя извлечения и сбоя объяснений. |
| Персонализация | История влияет на баллы после обязательных фильтров. Она не возвращает исключённый цвет/сорт и не позволяет неизвестной цене удовлетворить строгому бюджету. |
| Размер LLM-контекста | Python читает локальный снимок, фильтрует и ранжирует. При извлечении передаётся список гастрономических категорий, без карточек каталога; при объяснении — не больше пяти выбранных ID с короткими подтверждёнными причинами. |
| Автономная оценка | SHA-256 реальных HTML, отдельная временная SQLite, фиксированные сценарии, независимые сравнения с полями репозитория. Рабочая база и внешние сервисы не используются. |

Новые целевые регрессии находятся в `tests/test_evaluation.py`. Существующие
проверки парсера, URL, клиента, репозитория, API и отображения сохранены.

## Сохраняющиеся ограничения

- Приложение рассчитано на локальную демонстрацию. UUID не является аутентификацией;
  знающий UUID может обращаться к его истории. Развёртывание во внешнюю сеть
  требует отдельной защиты доступа; оно не выполнялось.
- HTTPS-изображения могут обращаться к внешнему хосту в браузере. Сервер не
  проксирует их; отсутствие изображения обрабатывается нейтральной заглушкой.
- Набор гастрономических категорий при извлечении не имеет отдельного лимита
  количества. Карточки всего каталога в модель не отправляются.
- Обрабатывается ограниченный словарь вкусов и блюд; отсутствие признака в
  источнике означает неизвестность, а не доказательство его отсутствия.
- Нет подтверждённых цен, поэтому бюджет нельзя гарантировать на реальном снимке.
- Производительность оценена только на небольшом локальном снимке; нагрузочного
  тестирования большого каталога и внешнего API не проводилось.
